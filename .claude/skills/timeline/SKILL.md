# Timeline Tab — Build Process

The Timeline tab is the vision document. It shows what the business becomes, node by node, period by period. It is not a task list, a project plan, or a roadmap. The roadmap carries the operational detail. The Timeline carries the strategic arc — what state each part of the business is in at each moment, and how that state evolves toward the vision.

---

## What It Is Not

- Not a task list. Every cell describes what the business IS at that moment, not what needs to be done. "Email platform live and capturing data" is a state. "Set up email platform" is a task. Tasks belong in the roadmap.
- Not a detailed plan. The detail lives one level down in functional documents and annual operating plans. The Timeline is the thread that connects them.
- Not uniform in granularity. The active year is broken into quarters. All subsequent years are annual. This reflects the reality that near-term planning is more certain than long-range planning.

---

## Tab Structure

**Row 1 — Timeframe:** columns for each period. Current year broken into quarters (Q1-Q3 as one column if substantially complete, then Q1-Q4 individually for the active planning year). Subsequent years as single annual columns.

**Row 2 — Theme:** one short phrase per period naming the strategic state of the business. These are not labels for tasks — they are descriptions of what the company is becoming. Examples: Foundation / Preparation / Infrastructure / Ignition / Amplification / Consolidation / Compound / Expand / Scale / Sustain.

**Row 3 — Company:** one summary statement per period describing the overall company state. This is the board-level view — what the business looks like as a whole in this period. It must align with the Theme and synthesize all node rows below it.

**Rows 4+ — Nodes:** one row per functional node, each cell describing the state of that node in that period. Node structure is client-specific — derived from the org chart, not from a template.

---

## Build Process

### Phase 1 — Read Everything

Before forming any view, read:
- All completed PLAN workbook tabs (Big Picture, Customer Objectives, Brand Objectives, Top Line) — the Timeline synthesizes these, so they must be understood first
- The org chart — node structure is derived from here
- All available strategy documents, journey maps, and briefs
- Any existing reference Timeline or roadmap examples for register guidance

**Never draft without reading the reference material first.** The register of the Timeline — visionary, state-describing, short — must be calibrated against real examples before any cell is written.

### Phase 2 — CEO Briefing

Before drafting, run a focused briefing with Michele to establish:

**What is already done?**
For the current year, explicitly confirm with the CEO what has already been completed before drafting the current-state column. Never assume the current state from general knowledge or strategy documents alone — recent activity may not be documented yet. This is the most error-prone step: facts already established (legal entity, tracking, product work, team changes) must be confirmed, not invented.

**What are the period themes?**
Propose the themes and get alignment before writing any content. Themes frame everything below them. If the themes are wrong, all the node content will be wrong.

**What is the node structure?**
Confirm which functional nodes belong in this Timeline based on the org chart and business model. Some nodes may need to be split (e.g. Finance and Legal as separate rows if both are material). Some may be combined. Do not use a standard template — derive from the client's actual org structure.

### Phase 3 — Draft the Company Summary Row First

Before drafting any node content, draft the company summary row (Row 3). This is the arc of the business in plain language — what the company looks like at each period as a whole.

Present this to Michele for alignment before proceeding to nodes. If the company arc is wrong, the node content will be wrong.

### Phase 4 — Draft Node Content

With the company arc agreed, draft each node row. For each cell:
- Describe the STATE of this node in this period — what it looks like, what it has become
- Use short, declarative phrases — two or three at most per cell
- Never use task language ("set up", "build", "create") — use state language ("live", "established", "running", "defined")
- Zero where nothing has happened yet — do not invent activity

**Register check — wrong vs right:**
- Wrong: "Set up email platform and begin list-building."
- Right: "Email platform live. List-building begun."
- Wrong: "Develop sourcing criteria and document external sourcing framework."
- Right: "Sourcing criteria documented. External sourcing framework defined."

### Phase 5 — Factual Accuracy Check

Before presenting, verify every cell against known facts:
- Does the current-state column reflect what has actually been done, confirmed by the CEO?
- Are there any facts invented from general knowledge that should have been confirmed? (legal entity status, operational systems, team structure, tracking — these are common error points)
- Does the node structure match the org chart?
- Do the themes align with the company summary row?
- Does the Timeline arc align with the revenue and customer sequencing in the other tabs?

### Phase 6 — Present as a Table in Chat

Present the full Timeline as a table in the chat conversation before writing to the workbook. This is lower cost than writing to a file and allows Michele to correct errors without a file round-trip. Only write to the workbook once the content is confirmed.

### Phase 7 — Write to Workbook

Write confirmed content to the Timeline tab. After writing, verify that all content transferred correctly — do not present the workbook without checking. Wrap text in all content cells.

## Node Structure Guidance

Nodes are derived from the org chart, not from a template. Standard node types to consider — include only those relevant to this client:

Under CBO (Brand): Brand, Content
Under CXO (Customer): Marketing, Service
Under CCO (Commercial): Distribution, Product
Under COO (Operations): Supply Chain, Logistics, IT, Finance and Legal, HR and Organization

Split nodes when both parts have meaningfully different evolution stories. Combine when one owns the other entirely at this stage of the business.

---

## Granularity Rules

- Current year (substantially complete): one column for the completed portion (e.g. Q1-Q3), then quarterly for the remainder
- Active planning year: quarterly (Q1, Q2, Q3, Q4)
- Subsequent years: annual only
- Never mix quarterly and annual in the same year column

---

## Excel Writing Rules

- Themes row: short phrase per cell, no punctuation
- Company summary row: one to two sentences per cell, declarative
- Node rows: two to three short phrases per cell, state language only, wrap text on
- No task language anywhere in the tab
- No formatting changes beyond what is explicitly requested
- Save as new version — never overwrite the source file
- After saving, verify all content transferred before presenting the file
